# 0005. Cloud Run, Vertex AI Configuration, Environment Injection, and Demo Auth Stance

- **Status**: accepted
- **Date**: 2026-10-21
- **Deciders**: flutter-architect

## Context

The Snap & Sell Python ADK agent runs Gemini multimodal inference on **Vertex AI** under the confirmed GCP project **`devhack-3f0c2`** (project name `devhack`) and is deployed as a container service on **Cloud Run**. Simultaneously, developers must be able to run the Python agent locally (`localhost:8080`) and connect to it from an Android emulator (`10.0.2.2:8080`), iOS simulator (`localhost:8080`), or physical device (Cloud Run HTTPS URL) without hardcoding URLs or committing secrets/API keys into the repository.

## Decision

1. **GCP Project, Region, and Vertex AI Authentication (ADC Only)**:
   - **Project ID**: `devhack-3f0c2`
   - **Region**: `us-central1`
   - **Authentication**: Use **Application Default Credentials (ADC)** exclusively (`GOOGLE_GENAI_USE_VERTEXAI=1`, `GOOGLE_CLOUD_PROJECT=devhack-3f0c2`, `GOOGLE_CLOUD_LOCATION=global` / `us-central1` as configured by `agents-cli`).
   - **Zero API Keys**: No `GEMINI_API_KEY` or service account JSON key files may be committed or bundled in the container or mobile app.
2. **Standardized `agents-cli` Local & Cloud Run Workflow**:
   - **Local Development**:
     - `agents-cli run` or `uv run uvicorn app.fast_api_app:app --host 0.0.0.0 --port 8000` (listens on port `8000` locally; `$PORT` / `8080` inside the Cloud Run `Dockerfile`).
     - `agents-cli playground` for interactive browser debugging.
   - **Cloud Run Deployment (`/google-agents-cli-deploy`)**:
     - Use `agents-cli deploy --mode prototype --project devhack-3f0c2 --region us-central1` (or Terraform in `deployment/terraform/single-project/` generated by `agents-cli scaffold create`), **only after explicit user confirmation**.
3. **Mobile Environment Injection via `--dart-define-from-file`**:
   - The Flutter app reads configuration strictly via `String.fromEnvironment` in `lib/core/config/app_config.dart`:
     - `AGENT_BASE_URL` (default `'http://10.0.2.2:8080'`)
     - `SNAP_SELL_CLIENT_TOKEN` (default `''`)
   - Commit non-secret environment templates under `apps/a2ui_snap_sell/mobile/config/`:
     - `config/local.json` / `config/dev.emulator.json`: `{"AGENT_BASE_URL": "http://10.0.2.2:8080"}` (or `http://10.0.2.2:8000` when running via `agents-cli run`; A2A routes are mounted at both `/` and `/a2a/app`)
     - `config/dev.ios_sim.json`: `{"AGENT_BASE_URL": "http://localhost:8080"}`
     - `config/prod.cloudrun.json` / `config/prod.json`: `{"AGENT_BASE_URL": "https://snap-sell-agent-devhack.us-central1.run.app"}`
     - Any file matching `**/*.local.json` remains gitignored per monorepo convention.

## Alternatives considered

- **Hand-written `deploy.sh` wrapping `gcloud run deploy` instead of `agents-cli deploy` / scaffolded Terraform** — rejected because `/google-agents-cli-deploy` and `/google-agents-cli-scaffold` provide a battle-tested `Dockerfile`, `agents-cli-manifest.yaml`, and Terraform configuration out of the box.
- **Bundling a Gemini API key in the Flutter app or Python `.env` committed to git** — rejected as a severe security anti-pattern and violation of monorepo rules.

## Consequences

- **Positive**: Zero secrets in git; identical code runs locally via `agents-cli run` and deploys via `agents-cli deploy`.
- **Positive**: Switching between Android emulator, iOS simulator, and Cloud Run requires only changing `--dart-define-from-file=config/<env>.json`.

## Compliance

`flutter-release-engineer` and `flutter-reviewer` check:
- No API keys, `.json` service account keys, or `.local.json` files exist in git status.
- `mobile/lib/core/config/app_config.dart` uses `String.fromEnvironment('A2UI_AGENT_URL', ...)`.
- `agent/Dockerfile` and `agent/agents-cli-manifest.yaml` match the `agents-cli scaffold create` Cloud Run template.
- Android `AndroidManifest.xml` permits cleartext traffic only for `10.0.2.2` and `localhost` via `network_security_config.xml` while enforcing HTTPS for Cloud Run domains.
