# Snap & Sell — Flutter GenUI Mobile Client (`mobile/`)

The Flutter mobile client for **Snap & Sell**, built on Flutter's
[GenUI SDK](https://github.com/flutter/genui) (`genui` + `genui_a2a`),
Riverpod 3.x, and the A2UI v0.9 protocol.

The app ships a single fixed screen (`EntryScreen`) where the user snaps or
selects a photo of an item to sell. Every subsequent screen in the selling
workflow is dynamically generated by the remote Python ADK agent and rendered
natively through GenUI's `SurfaceController` and custom `CatalogItem` widgets.

For the full system overview, backend agent details, and ADRs, see the parent
[`../README.md`](../README.md).

## Architecture

The mobile client follows the repository's layered `domain / data / ui`
architecture:

```text
lib/
├── core/
│   ├── config/app_config.dart          # String.fromEnvironment('AGENT_BASE_URL')
│   └── theme/snap_sell_theme.dart      # Material 3 theme & visual tokens
├── domain/
│   ├── entities/captured_photo.dart    # Resized JPEG bytes + metadata
│   ├── models/selling_session_state.dart
│   └── repositories/                   # ImageCaptureRepository & SellingTransportAdapter contracts
├── data/
│   ├── repositories/image_capture_repository_impl.dart
│   └── transport/genui_a2a_transport_adapter.dart  # Bridges SurfaceController <-> A2uiAgentConnector
└── ui/
    ├── catalog/
    │   ├── snap_sell_catalog.dart      # Catalog registration (BasicCatalog + 5 custom items + Button override)
    │   └── items/                      # Custom A2UI v0.9 CatalogItem implementations
    ├── features/
    │   ├── entry/entry_screen.dart     # Fixed initial photo capture screen
    │   └── selling_flow/selling_flow_host_screen.dart # Dynamic GenUI Surface host
    └── providers/
        ├── repository_providers.dart   # Single DI composition root
        └── selling_session_controller.dart # Riverpod Notifier managing session lifecycle
```

### State Management & A2UI Transport

- **Riverpod 3.x (`SellingSessionController`)**: Manages the high-level session
  state (`SellingPhase`, active `surfaceId` stack, in-flight loading state, and
  error banners) while delegating widget tree structure and reactive form
  bindings (`/draft/...`, `/pricing/...`) to GenUI's `SurfaceController` and
  `DataModel`.
- **In-Band Multimodal A2A (`GenUiA2aTransportAdapter`)**: Uses `genui_a2a`'s
  `A2uiAgentConnector` to stream A2UI v0.9 JSON-RPC + SSE messages against the
  ADK agent's `/a2a/app` endpoint, encoding captured photos as in-band A2A
  `FilePart` (`FileWithBytes`, `image/jpeg`) alongside `clientCapabilities` and
  the current surface `DataModel` snapshot.

### Custom Catalog Items (`lib/ui/catalog/items/`)

Registered under catalog ID
`https://snap-sell.devhack.dev/a2ui/v0.9/snap_sell_catalog.json`:

- `step_progress_item.dart` (`StepProgress`): 4-stage horizontal stepper
  (`Identify`, `Details`, `Preview & Price`, `Publish`).
- `detected_item_card_item.dart` (`DetectedItemCard`): Hero summary card with
  detected item title, category badge, confidence pill, and detected attribute
  chips.
- `photo_request_item.dart` (`PhotoRequest`): Interactive camera/gallery card
  for follow-up damage or odometer photos, dispatching `submit_RequestedPhoto`.
- `price_range_item.dart` (`PriceRange`): Low / recommended / high market price
  gauge with currency formatting and rationale.
- `listing_preview_item.dart` (`ListingPreview`): Editable final listing card
  with two-way `DataContext` binding (`/draft/title`, `/draft/price`,
  `/draft/description`), inline publish spinner, and double-tap protection.
- `snap_sell_button_item.dart` (`Button` override): Custom override of the
  standard A2UI `Button` that displays an inline `CircularProgressIndicator` and
  blocks duplicate taps while an A2A request is in flight.

## Configuration & Running

Runtime configuration is injected via `--dart-define-from-file` using the JSON
configs in `config/`:

| Config File | `AGENT_BASE_URL` | Target Environment |
| :--- | :--- | :--- |
| `config/prod.json` | `https://snap-sell-agent-823002731253.us-central1.run.app/a2a/app` | Deployed Cloud Run agent |
| `config/local.json` | `http://localhost:8000/a2a/app` | Local agent (with `adb reverse tcp:8000 tcp:8000` on Android USB) |
| `config/dev.emulator.json` | `http://10.0.2.2:8080/a2a/app` | Android Emulator -> host port 8080 |
| `config/dev.ios_sim.json` | `http://127.0.0.1:8080/a2a/app` | iOS Simulator -> host port 8080 |

### Commands

```bash
flutter pub get

# Run against Cloud Run production endpoint
flutter run --dart-define-from-file=config/prod.json

# Run against local agent on port 8000
adb reverse tcp:8000 tcp:8000   # Only needed for physical Android device over USB
flutter run --dart-define-from-file=config/local.json
```

## Testing

```bash
flutter analyze
flutter test
```

The test suite (43 tests) covers:
- Contract validation against `../contracts/snap_sell_catalog.json` and the 5
  few-shot A2UI v0.9 JSON examples (`test/contract/`).
- Widget tests for all 5 custom catalog items plus the `Button` loading-state
  override (`test/ui/catalog/`).
- Unit & widget tests for `SellingSessionController`, `EntryScreen`, and
  `SellingFlowHostScreen` using fake transport and image-capture repositories
  (`test/ui/`).
